# 画面一覧

仕様書（[01_requirements.md](../spec/01_requirements.md)）のコア機能を実現するための画面。  
URL は設計時点の案。会員登録・ログインはスターターキットの既存画面を使う。

## Day4（講義中に作る範囲）

| 画面名 | URL | ログインが必要か | 使えるロール | 表示するもの・できること |
|-|-|-|-|-|
| 会員登録 | `/register` | 不要 | 誰でも | 名前・メール・パスワードの入力。「主催者として登録」を選べる（既存画面にロール選択を追加） |
| ログイン | `/login` | 不要 | 誰でも | ログイン、パスワードリセットへのリンク（既存画面のまま） |
| イベント一覧 | `/` | 不要 | 誰でも | 公開中かつ開催前のイベントを開催日が近い順に表示。詳細へ進める |
| イベント詳細 | `/events/{event}` | 不要 | 誰でも（下書きと非公開は主催者本人と管理者だけ。ほかは 404） | 日時、会場、説明、券種ごとの価格・残り枚数・販売期間。券種ごとに枚数（0〜10 と残り枚数の小さいほう）を選び、「購入手続きへ進む」で選んだ枚数をセッション（`purchase.{event_id}`）に保存して購入内容の確認へ進む。販売期間外・売り切れの券種は選べない |
| 購入内容の確認 | `/events/{event}/purchase` | 必要（未ログインならログイン後に戻る） | ログインユーザー | 選んだ券種・枚数・小計・合計。「支払いへ進む」で注文（pending）を作り、注文完了へ進む。売り切れ・販売期間外などはエラー表示。選んだ枚数が無ければイベント詳細へ戻す |
| 注文完了（仮） | `/orders/{order}/complete` | 必要 | 注文者本人、そのイベントの主催者、管理者 | 「注文を受け付けました」と表示するだけの仮画面。Stripe を入れるときに支払い完了の画面にする |
| ダッシュボード（振り分け） | `/dashboard` | 必要 | ログインユーザー | 画面は持たない。ロール別にリダイレクトする（管理者 → `/admin/events`、主催者 → `/organizer/events`、参加者 → `/orders`） |
| 主催者のイベント一覧 | `/organizer/events` | 必要 | 主催者 | 自分のイベント一覧（イベント名、開催日、下書き / 公開中 / 非公開の状態、編集ボタン）。新規登録・編集へ進める |
| 管理者のイベント一覧 | `/admin/events` | 必要 | 管理者 | 全イベントの一覧（内容は未定。後の章で作る） |
| イベント登録 | `/organizer/events/create` | 必要 | 主催者 | イベント名、説明、会場、開始日時、終了日時を入力して下書きで保存。保存後は編集画面へ進む |
| イベント編集 | `/organizer/events/{event}/edit` | 必要 | 主催者（自分のイベントのみ） | イベントの編集・削除、券種の登録・編集・削除、下書き / 公開の切り替え。管理者が非公開にしたイベントは切り替えできない（主催者には戻せない）。券種は同じ画面の中で一覧と1つのフォーム（追加・編集で共用）で管理する。券種が1つも無いイベントは公開できず、最後の券種を削除できるのは下書きのときだけ（公開中と非公開では削除できない） |
| 注文確認 | `/orders/{order}` | 必要 | ログインユーザー（自分の注文のみ） | 作成した注文の内容（券種、枚数、合計金額）と状態。Day4 は「支払いへ進む」ボタンの手前まで |

## 平日課題

| 画面名 | URL | ログインが必要か | 使えるロール | 表示するもの・できること |
|-|-|-|-|-|
| Stripe Checkout（外部） | Stripe の URL | ─ | ログインユーザー | 注文確認の「支払いへ進む」から遷移し、カードで支払う。自作の画面ではない |
| 支払い完了 | `/orders/{order}/complete` | 必要 | ログインユーザー（自分の注文のみ） | Day4 の仮画面を置き換える。`session_id` が注文の Checkout Session と一致し、注文者本人が開いたときだけ Stripe に支払い状況を問い合わせて確定する。paid なら「購入が完了しました」とマイページへのリンク、pending なら「確認中」を出し `wire:poll.3s` で再確認する。合計 0 円の注文は購入確認の時点で確定済み（開いたとき pending なら確定する）。Stripe のセッションが失効した、または確認が20回（約1分）を超えたときはポーリングをやめ、「支払いを確認できませんでした」とマイページへのリンクを出す |
| 支払いキャンセル | `/orders/{order}/cancel` | 必要 | ログインユーザー（自分の注文のみ） | 支払いを中断した旨の表示、イベント詳細へ戻るリンク。開いただけでは何も変えない（GET で状態を変えない）。「注文を取り消す」を押すと、先に Stripe の決済ページを失効させ、成功したら `pending` の注文を `cancelled` にして枠を戻す。失効できなければ Stripe に状態を聞き、支払い済みなら確定、失効済みなら取り消し、不明なら取り消さずにエラーを出す。`paid` は変えない。注文者本人のみ（主催者・管理者は不可） |
| マイページ（注文一覧） | `/orders` | 必要 | ログインユーザー | 自分の注文の一覧（イベント名、日時、合計金額、状態） |
| 注文詳細（チケット一覧） | `/orders/{order}` | 必要 | ログインユーザー（自分の注文のみ） | Day4 の注文確認画面を拡張し、支払い済みなら発行されたチケットを表示。当日に見せる画面 |
| イベントの注文一覧と売上 | `/organizer/events/{event}/orders` | 必要 | 主催者（自分のイベントのみ） | そのイベントの注文一覧と売上合計 |

| 購入完了メール | ─ | Webhook の処理の中で送る |
